MiyaIP offers a comprehensive lineup of proxy types to match every use case — from long-term account maintenance that demands a fixed, consistent identity, to high-throughput data workflows that benefit from a constantly rotating IP pool. Understanding the differences between each type helps you choose the right product and avoid unnecessary costs or detection risk.

## Relay Mode vs. Native Mode

Every proxy type above can be used in either of MiyaIP's two connection modes. The right mode depends on whether you already have access to an overseas network.

<Tabs>
  <Tab title="Relay Proxy (中转代理)">
    In Relay mode, **MiyaIP provides the full transit relay chain** — you do not need your own VPN or overseas proxy. Your device connects to a MiyaIP relay server, which then routes your traffic through the residential IP exit node. This is the simplest setup and is recommended for most users.

    **When to choose Relay mode:**
    - You do not have an existing overseas VPN or proxy subscription
    - You want the fastest and simplest setup experience
    - You are configuring a mobile device (iOS or Android)
  </Tab>
  <Tab title="Native Proxy (原始代理)">
    In Native mode, you supply your **own first-hop overseas connection** (such as an existing VPN or proxy). MiyaIP's residential IP is then configured as a **SOCKS5 second hop**, layered on top of your existing connection. This creates a two-layer chain: your device → your overseas proxy → MiyaIP residential IP → destination.

    **When to choose Native mode:**
    - You already have a reliable overseas VPN or proxy
    - You need maximum IP authenticity (the exit IP is purely residential with no relay fingerprint)
    - You are using AdsPower or another anti-detect browser where chaining proxies is standard practice
  </Tab>
</Tabs>

## Supported Proxy Protocols

MiyaIP residential IPs are accessible over the following standard protocols, compatible with all major proxy clients and browsers:

| Protocol | Description | Recommended Use |
|----------|-------------|-----------------|
| **SOCKS5** | Low-level protocol that supports all traffic types including UDP | Mobile apps, anti-detect browsers, native proxy chaining |
| **HTTP** | Standard HTTP tunneling proxy | Desktop browsers, tools that only support HTTP proxies |
| **HTTPS** | Encrypted HTTP proxy (HTTP over TLS) | Desktop browsers, secure environments requiring encrypted proxy connections |

<Tip>
  For most use cases — especially on mobile and in anti-detect browsers — **SOCKS5** is the recommended protocol. It offers the broadest compatibility and supports all traffic types, not just web browsing.
</Tip>
